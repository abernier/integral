# CAM: ShopBot files from Fusion, from the command line

`pnpm cam <model>` makes the ShopBot OpenSBP files (`.sbp`) of a model with Fusion's CAM, driven through Fusion's local MCP server: no clicks. One file per sheet: `.docs/<model>/cam/<model>_<thickness>mm_<n>.sbp`, out of git, with a record of the run, `cam.json`.

Fusion decides what it can: how each part lies and where on the sheet (Arrange), the pockets (recognition), the toolpaths. The code only groups the parts by thickness, picks the tool, passes the values, and keeps the wedge setups Arrange cannot do.

**Simulate every `.sbp` before cutting** (Fusion, ShopBot Previewer), air-cut it first, check units, zero and tool against the machine.

## Prerequisites

- [ ] Fusion desktop (macOS or Windows), signed in. Fusion for Personal Use is enough (it posts ShopBot OpenSBP; its rapids run at the cutting feed, as the `.sbp` header says). Tested: 2706.1.17 (each run records it in `cam.json`).
- [ ] Preferences > General > API > *Fusion MCP Server (runs locally on this device)* on, port 27182 (else set `FUSION_MCP_URL`). Check: `pnpm cam --list-tools`.
- [ ] No command dialog open in Fusion during a run. Documents already open are not touched.
- [ ] The model's STEP, `.docs/<model>/<model>.step`, an assembly with one component per part: `nr build:parts`, or `--step`.
- [ ] The tools of [`tools.json`](tools.json) match the cutters on your ShopBot.

## Run

```sh
pnpm cam --list-tools                  # what Fusion's MCP server offers
pnpm cam zigzag-chair --dry-run        # the plan, nothing sent
pnpm cam zigzag-chair --force --keep   # then Simulate the setups in Fusion
pnpm cam --force                       # every model, every file made again
```

One small Python step per MCP call ([`fusion-job.py`](fusion-job.py)): import the STEP into a new unsaved document; each part's thickness (across its largest planar face, to 0.1 mm); per thickness, an Arrange feature per sheet (what does not fit goes on the next); per sheet a setup, its toolpaths, the post; per wedge setup the same; the document closed unsaved (also on Ctrl-C; `--keep` leaves it open). Files already there: nothing done (`--force` makes them all again, the old ones removed first; with `--only`, only the sheets of those parts, under the same names).

No file, reported: a part without a planar face, a thickness no tool cuts through, a part larger than the sheet.

## Parameters

Strongest first: CLI flag, manifest `defaults`, the default here. Same inputs and Fusion version: same bytes (checked: two runs, same hashes).

| Parameter | Default | CLI | What it does |
|---|---|---|---|
| STEP | `.docs/<model>/<model>.step` | `--step` | the parts' shapes and names |
| parts | all of the STEP | `--only A,B` | manifest `skip` leaves a part out |
| post | `shopbot` | `--post` | the Fusion library post whose vendor or description contains it, the shortest such (ShopBot OpenSBP) |
| sheet | `[2440, 1220]` | `--sheet 2440x1220` | the stock board, mm |
| spacing | 12 | `--spacing` | between two parts on a sheet |
| frame | 10 | | kept free along the sheet's edges |
| tool | the narrowest of `tools.json` whose flutes reach `thickness + overcut + reach` | `--tool` | the cutter, per sheet |
| reach | 1 | | flute length to spare when choosing the tool |
| overcut | 0.3 | | how far the outline cuts below the sheet, into the spoilboard |
| stepdown, stepover | the tool's preset | | deepest pass (even passes); widest step across a pocket |
| pocketStockToLeave | 0.5 | | wood left on pocket walls and floors for a finishing pass; 0: to size |
| tabs | `{ count: 4, width: 6, height: 3 }` | | rectangular, per contour; `false`: none |
| margin | 5 | | stock around a part in its own (wedge) setup |

Fixed: parts turned any angle and laid largest planar face down (manifest `flip`: up), part-in-part off; stock = the sheet, its bottom on the parts'; WCS at the sheet's top, x-min y-min corner; a 2D pocket on the pockets Fusion recognises (holes the tool fits in, any corner radius); a 2D contour outside each part's silhouette, through; feeds and speeds from the tool's preset; coolant off; all else Fusion's defaults. The grain is not taken into account.

## Tools

[`tools.json`](tools.json), flat end mills, built into Fusion's tool JSON by [`machining.ts`](machining.ts). **Defaults: check them against your cutters, wood and machine.**

| id | Ø mm | flute length mm | tool # | rpm | cutting mm/min | plunge mm/min | stepdown mm | stepover mm |
|---|---|---|---|---|---|---|---|---|
| `flat-6-2f` | 6 | 25 | 1 | 18000 | 2500 | 800 | 6 | 2.4 |
| `flat-8-2f` | 8 | 35 | 2 | 18000 | 3000 | 900 | 8 | 3.2 |
| `flat-12-2f` | 12 | 50 | 3 | 16000 | 3500 | 1000 | 10 | 4.8 |

## The manifest

`.docs/<model>/<model>.cam.json` (generated by the build, not yet), else `<model>/cam.config.json`. Optional. Unknown keys are errors.

```json
{
  "version": 1,
  "defaults": { "post": "shopbot", "sheet": [2440, 1220], "tabs": { "count": 4 } },
  "parts": [
    { "part": "SeatCleat", "skip": true, "note": "the table saw" },
    { "part": "Back", "flip": true },
    { "part": "Seat", "setups": [{ "name": "wedge8", "wedge": 8, "rotate": [8, 0, 0], "cut": "squared" }] }
  ]
}
```

| Key | |
|---|---|
| `defaults` | `post` and the parameters above |
| `parts[].part` | the STEP component's name |
| `parts[].skip`, `note` | no file for this part; why |
| `parts[].flip` | laid largest planar face up instead of down |
| `parts[].setups` | setups of the part alone, one file each, `<Part>_<name>.sbp`, beside its sheet |
| `setups[].rotate` | `[x, y, z]` degrees, in that order, about the part's box centre |
| `setups[].wedge` | the wedge's angle, for the maker |
| `setups[].cut` | `"squared"`: one 2D contour along the bottom edges of the faces upright as turned but not as modelled (the part must be modelled flat), on the waste side, to `overcut` below their lowest point, no tabs; the tool chosen for that depth. Else pockets and outline |

## The record: `cam.json`

Per file: its sha256; for a sheet, its thickness, number, parts, where they lie (`partsBox`, mm from the corner), size, spacing, frame; for a wedge setup, its turn, depth, margin; the tool and every value given to Fusion; the deepest cut; the post and its version; the Fusion version; the sha256 of the inputs (STEP, manifest, `tools.json`, `fusion-job.py`, `machining.ts`, `cam.ts`).

## In the workshop

- A sheet is one stock board clamped on the ShopBot, by default 2440 x 1220 mm, of one thickness.
- One `.sbp` per sheet: every part of that thickness, nested by Fusion. `<model>_<thickness>mm_<n>.sbp`: `n` is the next sheet when one is full.
- Zero: the top of the sheet, at its front-left corner (x-min, y-min).
- Parts stay held by tabs: cut them free, sand the stubs.
- A wedge file (`<Part>_<setup>.sbp`) is a second pass on a part already cut from its sheet, laid on its wedge; its zero: the top of the part as it lies on the wedge, 5 mm (`margin`) out from the front-left corner of its box.
- Simulate, then air-cut, before cutting wood.
